# 画布必须盖满面板（全屏覆盖）—— 否则底部露出「上一款应用」的残留帧（伪闪烁）

> 检索关键词：残留帧 / 花屏 / 底部条 / 页标签闪烁 / 画布高度 / 分辨率不符 / 双缓冲 / 伪闪烁 / 全屏覆盖 / canvas / 1280x750
> 适用：**全屏应用**（有意留黑边/多分辨率分目录的工程另按各自主张）。

## 现象

真机某条边（实测 = 屏幕底部）长期显示一块**不属于本应用**的内容——例：上一款部署过的应用底部那条
「第 N / M 页　<页名>」状态行；页面刷新/切页时这块内容**会闪**，甚至闪出另一款应用某一页的文案。
先怀疑「逻辑问题」时往往会查错方向：**它不是本应用的控件**。

## 根因（两条叠加）

1. **画布 ≠ 面板**：布局 `resolution.height` 比面板可视高度小（实测 `1280×750` vs 面板 `1280×800`）
   → 引擎只绘制画布范围，面板其余行**本应用从不写入**。
2. **framebuffer 双缓冲**：未绘制区域保留**上一次被写过的**内容（= 前一款部署过的应用最后一帧）。
   两块 buffer 的残留内容往往不同 → 每次刷新换 buffer 就换一次残留画面 → 看起来像「闪烁/花屏」。

## 诊断三步（零猜测，别先改代码）

1. **确认在跑哪套包**：`adb pull /tmp/ui/main.ftu` → `fui unpack` → 与本地 `ui/main.ftu` 比 md5；
   再 `adb pull /tmp/lib/libzkgui.so`，在二进制里搜本工程独有字符串（如状态行格式串）核对。
2. **把可疑文案丢进反解析出的 json 里搜**：搜不到 ⇒ **它不属于本应用**（= 残留帧）。
   （同时可确认参数：`resolution`、根 `position`、`backgroundColor`。）
3. **连续抓两帧（同一页、不动手）只比那块区域的 bbox**：
   `ImageChops.difference(a.crop(region), b.crop(region)).getbbox()` —— **两帧不同 = 换 buffer 时残留内容在变**，
   这正是真机看到的「闪烁」来源（实测同一块区域两帧分别是 `第 1 / 8 页　滚轮基础` 与 `第 8 / 8 页　日历`）。

## 修法（最小改动、几何零位移）

* `ui/main.json`：把 **`resolution.height`** 与**根节点 `position.height`** 一起改成**面板可视高度**（750 → 800）。
  * 控件全是绝对定位 → 位置不受影响；改前先确认根 `backgroundColor` 不是透明/黑（它负责把补齐区刷成正常底色）。
* `fui pack` 出新 ftu → push 到设备 → **温和重启**应用（`kill -TERM <pid>`，init respawn）。
  平台禁 reboot 的照旧禁（见 `devflow/adb-and-device-selection.md`）。
* **只改布局 = 不用重编/重推 `.so`**，把影响面压到最小。

## 验收判据（机器可判，0 token）

| 判据 | 期望 |
|---|---|
| 补齐区像素 | == 根背景色（应用已绘制） |
| 同页连抓两帧，补齐区 diff bbox | `None` |
| 强制切页（tap 导航/滑动）后再抓，补齐区 diff bbox | `None` |
| 全帧 diff（修复前 vs 后） | 只差补齐区（+ 重启导致的状态行重置），其余零变化 |

## 落地注意（防复发）

* 生成器（`gen_*.py` / html2json 模板）里**别把画布高度写死成"内容高度"**：
  **画布 = 面板可视区**，内容不够就让底部留白条，不要留"没人画"的区域。
* 多屏复用同一工程 → 按屏生成 `ui/<分辨率>/`，或按最大面板生成 + 运行期布局。
* 验收脚本建议加一条硬断言：**画布分辨率 == 目标面板可视区**（本缺陷修复前无任何检查能发现它，
  因为所有几何断言都锚在控件自己的盒子里）。
