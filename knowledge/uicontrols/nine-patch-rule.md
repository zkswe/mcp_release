## 五条规则（必须全部满足）

1. **marker 线颜色必须为纯黑不透明 `(0,0,0,255)`**，禁止透明 `(0,0,0,0)`（透明 marker 设备端识别不到，等同没标）
2. **top / left 黑线：只画中间拉伸段**，排除左右/上下 radius 像素的倒角区（圆角弧线内不能有黑线）
3. **right / bottom 黑线：宽度与拉伸区（stretch 区）同宽**——right 竖线范围 = left 拉伸段（y0..y1），bottom 横线范围 = top 拉伸段（x0..x1），四边 marker 语义完整（拉伸区 + 内容区）
4. **marker 线宽 = 1px，紧贴图片边缘**（top/bottom 在 y=0 / y=h+1，left/right 在 x=0 / x=w+1）
5. **marker 必须在所有绘图完成后最后绘制**，且不能被后续 alpha 操作覆盖（先画图 → 扩边 → 最后画 marker；任何 putalpha/裁剪必须发生在画 marker 之前）

## 生成流程（Pillow 示例）

```python
from PIL import Image, ImageDraw

def to_9patch(img, radius, out_dir, name):
    """普通图 → .9.png：四周扩 1px 透明边，四边黑线标记（FT-009）"""
    w, h = img.size
    out = Image.new("RGBA", (w + 2, h + 2), (0, 0, 0, 0))
    out.paste(img, (1, 1))          # 内容图居中，四周留 1px marker 边
    d = ImageDraw.Draw(out)
    x0, x1 = 1 + radius, w - radius  # top/bottom 拉伸段（排除倒角）
    y0, y1 = 1 + radius, h - radius  # left/right 拉伸段（排除倒角）
    black = (0, 0, 0, 255)           # 规则1：纯黑不透明
    # 规则2+4：top/left 只画中间段，1px 贴边
    if x1 > x0:
        d.line([(x0, 0), (x1, 0)], fill=black, width=1)
    else:
        d.point((1 + w // 2, 0), fill=black)
    if y1 > y0:
        d.line([(0, y0), (0, y1)], fill=black, width=1)
    else:
        d.point((0, 1 + h // 2), fill=black)
    # 规则3：right/bottom 与拉伸区同宽
    if y1 > y0:
        d.line([(w + 1, y0), (w + 1, y1)], fill=black, width=1)
    else:
        d.point((w + 1, 1 + h // 2), fill=black)
    if x1 > x0:
        d.line([(x0, h + 1), (x1, h + 1)], fill=black, width=1)
    else:
        d.point((1 + w // 2, h + 1), fill=black)
    out.save(os.path.join(out_dir, name))
    return os.path.join(out_dir, name)
```

## 验证方法

生成后检查 marker 像素（四边 1px 环）：
- `img.getpixel((x0, 0)) == (0, 0, 0, 255)`（top 起点，纯黑不透明）
- `img.getpixel((0, y0)) == (0, 0, 0, 255)`（left 起点）
- 倒角区无黑线：`img.getpixel((1, 0))` 应为透明（不落 marker）
- right/bottom 黑线范围与 top/left 一致

## 常见坑

- 只画 top/left 不画 right/bottom（旧版 gen_res.to_9patch 的 bug，v0.6.10 修复）→ 内容区标记缺失
- marker 用 `(0,0,0,0)` 或半透明 → 设备端不识别
- 扩边前画 marker → paste 内容图时被覆盖
- 圆角后 putalpha 裁剪 → marker 被 alpha 清掉（必须先裁完再画 marker）
- 9-patch 黑线画进倒角弧线内 → 圆角拉伸变形

> ⚠️ 注意：**ZKSeekBar 不解析 9-patch**（marker 会画成黑框），
> SeekBar 背景一律用普通 .png，禁止 .9.png（check_all.py 交付全检第 10 项强制校验）；
> 本规则适用于按钮/卡片/面板/轨道等支持 9-patch 的控件。

## 进阶：方块底图刷平卡片的**底部圆角**（2026-09-17 真机，案例 `projects/translate/tdesign-miniprogram`）

**现象**：圆角卡片（如对话框/动作面板）的**底部两个圆角变方**，上半部分圆弧却好好的；
客户反馈的原话常常是「**底部倒角不正常，应该是按钮的方块背景盖到了**」。

**根因**：卡片底部那排动作按钮用的是**方角** `.9.png` 底图（`btn_flat` 这类），按整行铺在卡片底部
→ 把卡片自己的 12px 圆弧**刷平**。关键在于**两层各自的画法就不一样**：

| 事实（本次实测，平台通用） | 含义 |
|---|---|
| **`.9.png` 底图的着色区 = 控件盒左右下各内缩 1px** | 按钮比盒子略小一点，但**角还是方的** |
| **普通 PNG**（textview 的 `backgroundPic`，如卡片/药丸）**严格 1:1 画在盒子里** | 卡片圆弧本该原样透出 |

改前实测（设备帧，8 个带按钮的弹窗里 **7 个中招**）：卡片底边往上第 1~6 行白区 inset 只剩 **1~2px**
（理想是 `7/5/4/3/2/2`），**单行最大偏差 6px**，合计 **28 个偏差行**。

### 做法（两条路，选「挖空」）

**✅ 推荐：按位置生成「带下圆角的动作行底图」+ 角区整块挖空（透明）**

- 按按钮**实际位置/宽度**出图：整宽单按钮 / 两按钮行的左 / 两按钮行的右，各带对应的下圆角
  （左按钮才左下圆角、右按钮才右下圆角），另出 **按下态变体**（`_p`）。四张底图各按**实际控件尺寸**出
  （案例：311×56 整宽 / 155×56 左 / 155×56 右 / 1024×56 面板取消），图与盒 1:1，不依赖拉伸。
- **角区整块挖空（透明）而不是自己画弧**：按钮叠在卡片**之上**，若按钮自己画圆弧，弧边的半透明像素
  会与卡片自己的弧边**二次 alpha 混合**（实测该像素 178 → 217，**弧边发白变硬**），逐行 inset 仍会偏 1px。
  挖空后按钮根本不碰卡片圆角，**卡片自己的圆弧原样透出 → 与「没被盖住」的理想圆弧逐像素一致**。
- 9-patch marker 要**逐角重打**（拉伸段避开挖空区），因为常见的 `gen_btn9` 只支持四角同半径。
- 按下态（`:active`）用「**同半径真圆弧 + 灰底**」：按下时圆角跟着变灰（挖空版在按下时会留一个角区），
  与设计稿一致；代价是弧边有 1px 级 AA 差异（可接受）。

**❌ 不推荐：让按钮底图直接画一条与卡片同半径的圆弧**（二次混合发白，逐行 inset 仍偏）

### 验收口径（像素级，可复用）

从卡片左右边缘往内扫，第一个亮度 ≥200 的像素位置 = 白区 **inset**；
**理想值** = 卡片底图 alpha 合成到「该行卡片外侧实测遮罩色」上（即「没被按钮盖住时应有的样子」）；
**偏差 = 实测 − 理想**，逐行取卡片末 14 行，`|偏差| ≤ 1px` 视为 AA 噪声。

| 指标 | 改前 | 改后 |
|---|---|---|
| 8 个弹窗里「底部圆角偏差」弹窗数 | **7 / 8 FAIL** | **0 / 8 FAIL** |
| 偏差行数合计 | **28 行** | **0 行** |
| 单行最大偏差 | **6 px** | **0 px** |
| action-sheet「取消」整宽按钮（同根因） | 4 行 / 最大 6px | **0 / 0px** |

改后设备帧的逐行 inset 序列（`10,7,5,4,3,2`）与卡片底图自己的理想 r=12 圆弧**逐像素相等**
——不是「接近」，是同一条曲线。

### 排查清单（圆角被盖住类）

- [ ] 找出压在圆角卡片**底部**的方块/直角底图（整行按钮底图、色块、分隔带）
- [ ] 卡片自身用的是普通 PNG 且**严格 1:1**（不要用 .9.png，否则圆弧本身也会被拉伸）
- [ ] 动作行底图**按按钮位置分左右/整宽出图**，角区**挖空**
- [ ] 按下态也带圆角（灰底），否则按下瞬间角落露白/露方
- [ ] 同根因扫一遍：**动作面板底部「取消」整宽按钮**、任何「色块压在圆角底」的形态
- [ ] 逐弹窗抓帧 + 逐行量 inset（只看一张容易漏：案例 8 个弹窗里 7 个中招）

> 同类形态：药丸（pill）自带 r=6 圆角、上面只有居中文字/图标 → **没中招**；
> 阶段性的「徽标/标签/进度条」是独立小件、底部无覆盖物 → 也没中招。**先定位形态再改**。
