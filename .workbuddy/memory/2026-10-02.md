### 关键坑（重要，下次直接复用）

1. **`ast` 的 `col_offset` / `end_col_offset` 是 UTF-8 字节偏移，不是字符偏移。**
中文行上按字符切片做替换会把后面的代码啃掉（表现为 `"""umps(...` 这种诡异语法错误）。
正确做法：在 `src.encode('utf-8')` 的字节流上按 `acc[line-1]+col` 替换，最后 decode。
2. 同一行 `"""` 开头 vs 独立成行的两种 docstring 风格要分别处理；独立成行时
起始引号前的缩进在替换区之外，渲染时**不能再补 pad**，否则多一层缩进 → IndentationError。
3. 候选文件**别落在仓库内**：`scripts/lint_silent_except.py` 递归扫仓库所有 .py，
留一份 kb_tools.py 副本（temp/ 也照扫）会报 "new silent except" 假阳性。写到系统临时目录。

**口径**：资料里不该出现「<人名> 2026-09-12 确认」这类口语。资料的价值是**结论 + 依据 + 日期**，
不是「谁说的」——人名口语会让 AI 把口头确认当权威依据，对外也不专业。

**规则集**（772 种写法、无统一句式，必须分类处理）：

| 场景 | 处置 |
|---|---|
| 主语位（行首 / 列表项 / 句末标点后 / `**人名**` / 「人名的」） | → 中性主语「**需求方**」 |
| 括号/方括号内的依据注记（`（人名 日期 确认）`） | 删人名，**留日期与结论** |
| `（人名：原话…）` | → `（**现场反馈**：…）` |
| `人名 原话` / `人名将补充` | → `现场原话` / `待补充` |
| 括号内只有人名（`（人名）`） | 整个括号删掉 |

**★ 踩的坑（差点大面积破坏）**：规则里最初有三条「删空括号」——
`（\s*）` / `\(\s*\)` / `\[\s*\]`。**半角那两条会把代码里的 `()`、`[]` 一起删掉**：

`def bundled_adb_dir():` 变成 `def bundled_adb_dir:`。

- 但 `.md` 没校验、**已写坏** → `git checkout` 恢复那 3 个纯清洗文件后重做；
- 修法：**清理规则只许作用于全角标点**（`（），。「」`），半角一律不碰（那是代码）；
  「括号内只有人名」改用**整体匹配**（`（人名）`→删），而不是「先删人名、再清空括号」两步。

**名单写成 unicode 转义**（写明文会让门禁脚本扫中自己，自指）。

## hardware_catalog 的上下文开销：区分「数据源」与「随调用返回」

**问题（用户提）**：catalog 37 KB，描述是不是太多、会不会撑爆 AI 上下文？
