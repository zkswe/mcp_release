# blur — 平台说明（实测值，没测的一律标“未验证”）

组件：`components/blur/`（源码型：include/ + src/ + example/）
口径：所有耗时 = **真机实测**，1 次调用 = 「封面 -> 目标尺寸铺底图」全链路（本组件内部时间，
不含调用方写 PNG/上屏）；同一配置跑 N 次取**最小值**（设备有负载抖动，取 min 比 avg 稳）。

## 1. 结论速查

| 场景（真机 F133 / C906） | 推荐档位 | 实测 |
|---|---|---|
| 1280x800 铺底、**输出 320x200 缩图**（显示层拉伸） | BOX3 + 缩图（r=8, down=1） | **71~88 ms**（RVV 版 71 ms） |
| 同上，但输出就直接是 1280x800 全尺寸 | BOX3 + down=4 + 放大回 | 447~516 ms |
| 只要极快（160x100 铺底） | BOX3 + down=8 | 54 ms |

**别用的两个档**（都在真机实测过，慢或没意义）：
- `SEP_FIXED`（定点核 + 256 项乘积查表）：C906 上 **比 float 还慢**（65 taps × 256 × 2B = 33 KB 核表
  装不进 L1，每米像素都在打内存）→ 1280x800 实测 **40539 ms**。
- `NAIVE2D`：只当正确性参考，1280x800 r=8 要 **27009 ms**。

### 2.2 RVV 0.7.1（同一份源码，整工程 `-march=rv64gcv0p7` 编出来）

- 工具链：Xuantie-900 GCC 10.4.0 **支持** `-march=rv64gcv0p7`（实测编译通过，产物里有 `vsetvli/vfadd/vmulhu/vnsrl`）。
- **单文件 `__attribute__((target("arch=...")))` 不支持**（GCC 10.4 实测：`warning: target attribute is not supported on this machine`）
  → 要用 RVV 只能**整工程**带向量编译开关，做不到“只给这一个 .cpp 开”。
- 设备内核支持向量上下文（`/proc/cpuinfo` isa 含 `v`），RVV 代码在真机**跑通不崩**、结果正确。
- **收益有限**（best-of-3，同配置对比标量构建）：

| 配置 | 标量 (ms) | RVV (ms) | 提速 |
|---|---|---|---|
| 640x640 -> 320x200 r=8 | 88 | 71 | +19% |
| 1280x800 -> 320x200 r=8 | 133 | 118 | +11% |
| down=2 -> 640x400 | 230 | 186 | +19% |
| down=4 -> 1280x800（放大回） | 516 | 452 | +12% |

原因：三趟盒式里**横趟有像素间依赖**（滑窗串行）只能走标量，竖趟向量化了也只占一半；
且 C906 的 RVV 0.7.1 通道数少（VLEN=128），u16 车道一次 8 个。

### 2.3 内存峰值（1280x800 目标）

`prep` 峰值 ≈ 平面池 2×(w·h·4) + 临时 w·h + 裁切缓冲 + 输出缓冲：
- 输出 320x200（推荐档）：**< 2 MB**
- 输出 1280x800（down=4）：**≈ 19 MB**

### 2.4 真机整链路（播放页实测，含解码与落盘）

封面 320x320 PNG → 320x200 铺底（r=8, down=1, 压暗 84/256）：
**解码 60 ms + 模糊 103 ms + PNG 落盘 231 ms = 395 ms**（`TaskRunner` 后台线程，UI 线程不阻塞）。
→ PNG 编码占了 58%，后续可换 BMP/降分辨率（见工程 REPORT「待拍板」）。

## 4. 已知限制

- 只吃 **4 字节/像素**位图（BGRA）；3 字节源请调用方先补 alpha（工程侧 `BlurBg.cpp` 就是这么做的）。
- `radius` 上限 128；`down ∈ {1,2,4,8}`（>8 收益见顶）。
- `threads` 字段保留未实现（当前单线程；C906 单核，多线程只会更慢）。
- RVV 档与标量档的除法口径差 1 LSB（`vmulhu` 截断 vs 标量 `+0.5` 舍入），实测 err_max 差 2。
