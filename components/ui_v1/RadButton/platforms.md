> 口径：**Z21（2026-09-16）与 V85X（2026-10-03）已真机验收**；其余平台按 2026-10-03 口径标 `➖ 不逐平台验`（UI 控件只做 V85X 单平台代表验收，见 `platform_capabilities.json` 的 `verificationPolicy`）。

## 1. Z21（1024×600，easyui 2.6.0）—— 已真机验收

### 1.1 圆角边缘质量（AA 带像素 vs 16×16 超采样理想覆盖率，单位 = 0~255 通道误差）

| 路线 | 画法 | AA 带像素 | 平均 | p95 | 最大 | >30 占比 | 证据 |
|---|---|---|---|---|---|---|---|
| **A 平台原生**`fillRect(l,t,w,h,r)` r=4 | `MODE_HARD` | 7 | 10.0 | 12 | 12 | 0% | `evidence/01…` |
| **A 平台原生**r=8 | `MODE_HARD` | 11 | **19.6**| **34**| **34**| **36%**| `evidence/07` |
| **A 平台原生**r=14 | `MODE_HARD` | 21 | 8.2 | 13 | 14 | 0% | `evidence/06` |
| **B 本包 AA**r=4（默认） | `MODE_AA` | 7 | **1.4**| 2 | 2 | 0% | — |
| **B 本包 AA**r=8 | `MODE_AA` | 11 | **1.8**| 3 | 3 | 0% | `evidence/07` |
| **B 本包 AA**r=14 | `MODE_AA` | 21 | **2.0**| 5 | 5 | 0% | `evidence/06` |
| **C 切图**`.9.png` 资产本身（4× SS + LANCZOS） | PC 出图 | 21 | 10.6 | 18 | 22 | 0% | — |
| **C 切图**设备上（200×56 → 300×56 拉伸） | `button__N` + `picTab` | 21 | 10.0 | 17 | 21 | 0% | `evidence/08` |
| C 的**反例**：同资产当 r=13 用 | `button__N` | 19 | **59.1**| **122**| **122**| **74%**| — |

结论（可直接引用）：

1. **平台 `fillRect(radius)` 是抗锯齿的，但很粗**：r=8 时平均误差 19.6、**36% 的弧带像素误差 >30**（肉眼可见台阶），
偏差方向一致（实测像素恒比理想更浅，如 `#98CCF7` vs 理想 `#75BDF6`）→ 表现为「一圈发虚的台阶」。
   **所以「平台自带圆角」不等于「圆角够看」——这是本包存在的直接理由。**
2. **本包 AA 基本贴着理想**（平均 1.4~2.0、最大 5/255，比平台原生好 4~10 倍）；
实现 = 几何覆盖率（8×8 超采样/像素）+ 与已知底色混色，不是估的、也不是重采样出来的。
3. **切图路线质量够用且 9-patch 拉伸不额外掉质量**（10.0 ≈ 资产本身 10.6）——
但**半径/尺寸/状态色全烧在资产里**：同一张 r=14 资产当 r=13 用，误差立刻 59.1。
   → 静态美术件照旧用切图；**要运行时任意尺寸/半径/四态，只有 B**。

### 1.2 ZKPainter 平台事实（本包全部结论的来源，实测）

| 事实 | 实测证据 | 对 API 的影响 |
|---|---|---|
| `setSourceColor(0xRRGGBB)` **无 alpha**| `#2196F3` 画出来就是不透明纯色；`mix()` 混色是唯一的「半透明」替代 | `Style::bg` 必须由调用方给对（AA 混色基准）。**另外平台也没有 clip/mask**→ 「内嵌图形被外层轮廓裁掉」只能自己逐像素算（0.1.1 的图层叠加，见 §5.1） |
| **`erase()` 擦出来是「不透明黑」**| 只 `erase` 不补画的地方 = `#000000`（真机见：只跳过一个像素就是黑块） | 画法**必须自己铺底**（本包 0.1.0 起先铺 `Style::bg`）↔ 排错表第 1 条 |
| `fillRect(l,t,w,h,radius)` 有**粗**AA | §1.1（r=8 平均 19.6 / 36% >30） | `MODE_HARD` 只作对照/兜底 |
| `fillArc` / `drawRect` 可用（含圆角与线宽） | `evidence/01` 的 ④ 探针：圆环 + 2px 圆角描边正常 | 本包不依赖；示例用于「painter 原生能力」对照 |
| `getPosition()` 可用；`getParent()` / `getAbsolutePosition()` **不可用**| 设备端 `libeasyui.so` 未导出（用过会整屏黑） | 本包只用 `getPosition()` 取宽高，坐标一律局部 |
| `.9.png`（9-patch）**平台认**| 200×56 资产放进 300×56 按钮，**角落 1:1 保留、中段拉伸**（`evidence/08`） | 切图路线可用；注意内容会**内缩 1px**（marker 边不裁掉），比对时按 `box=(x+1,y+1)` 对齐 |
| painter 不自动重绘 | `refresh()` 才画；`onUI_show` 要再刷一遍 | 硬约束（写进 README §6） |

**测量方法**（0 token，纯像素，可复现）：

```powershell
# 与理想覆盖率比（主判据）
python <example>\tools\aa_ideal.py rb_01.png --box 456,198,200,56 --radius 14 --corner tl --label AA_r14
# 中间档档数 / 占边界像素比例（辅助判据）
python <example>\tools\aa_measure.py rb_01.png --region 456,198,470,212 --label AA_r14_corner
```
（`--box` 是控件盒的屏幕绝对坐标，`--corner` 选 tl/tr/bl/br；脚本对每个像素做 16×16 超采样求理想覆盖率。）

## 3. 上其它平台前必查 4 条（每条都可能翻车，别省）

1. **`erase()` 的擦除色是否也是不透明黑**：本包靠「先铺 `Style::bg`」规避；
若某平台的 `erase` 是透明/不清屏，则铺底无害（只是多一次 fillRect），但**要确认铺底真的生效**
   （现象：圆角外出现非底色）。自查 = 抓一张首帧，看四个角的颜色是否 == `Style::bg`。
2. **`fillRect(l,t,w,h,radius)` 是否还带粗 AA**：跑一次 `MODE_HARD` 与 `MODE_AA` 同屏对照，
用 `aa_ideal.py` 各算一遍（数字口径与 §1.1 一致）。若某平台**硬边**（AA 带像素 = 0），
那本包的 AA 就是「唯一能出平滑圆角」的路（更值得用）。
3. **1×1 / 1×(n) 的小 `fillRect` 是否正常**：本包抗锯齿靠逐像素画（合并成行 span）。
极端平台若吞掉 1px 高的矩形，圆角会缺一块 —— 自查 = 示例屏 ①② 两排的圆角是否完整。
4. **`setSourceColor` 的色序/位宽**：抓图确认 `#2196F3`（示例用的蓝）没有被换成红蓝互换
   （若互换：截屏工具传 `pixel=rgba/bgra` 是一回事，真机色序是另一回事，要分开确认）。

## 4. 已知限制（跨平台共识，与 README §6 一致）

- AA 只对**纯色底**精确（`Style::bg`）；压在图片/渐变上会有一圈偏差（painter 无 alpha）。
- 不做阴影/渐变/内边距/文字排布（文本用 `textview` 叠）。
- `refresh()` 必须显式调；painter 不自动重绘。
- 半径被夹在 `min(w,h)/2`（控件盒太小会自动变小）。


## 5. 触摸 / 开关 / PILL 形态（2026-09-16 晚新增，Z21 实测）

### 5.1 没有引入任何**新的**平台符号（这才是能跨平台的原因）

本轮新增的三个能力（命中 / 按下态 / 药丸）全部站在原有那 4 个 painter API 上：

| 能力 | 用到的平台 API | 说明 |
|---|---|---|
| 命中判定 `hitTest/onTouch` | **无**（纯几何 + 业务给的矩形） | 包内不查祖先链、不碰 `getAbsolutePosition()` / `getParent()` |
| 按下态 / 翻转 / 重绘 | `setSourceColor` + `fillRect` + `erase` + `getPosition` | 与 §1.2 那 4 条一致 |
| 药丸圆钮（正圆） | `fillRect(l,t,w,h,radius)`，`radius = dia/2` | **不依赖 `fillArc`**；钮用「边长 dia、圆角 dia/2」的圆角矩形算覆盖率。**⚠️ 但钮不能自己铺 `dia×dia` 底色盒**（那是 0.1.0 的 bug：盒外角落在药丸端头半圆之外 → 露方角）—— 0.1.1 起改走**图层叠加**：逐像素 `mix(mix(track, Style::bg, 1-P), knob, K)`，`P == 0` 不画 |

> 换平台/换内核时，只有这 4 个 API 的行为需要复核（§3 那 4 条），触摸那部分是纯 C++ 逻辑。

### 5.2 Z21 上的实测结论（本轮）

| 项 | 结论 | 证据 |
|---|---|---|
| 命中口径 | `setRect()` 给**绝对屏幕坐标**（= `MotionEvent::mX/mY` 口径）后，`onTouch()` 命中与平台按钮命中一致（同一批坐标既能点中平台按钮、也能点中包的矩形） | 案例 `z21/evidence/zzb_*`（点药丸翻转、按住=按下态） |
| 消费语义 | activity 触摸回调 `onmainActivityTouchEvent` 里返回 `true` = 事件被吞（平台控件收不到）；返回 `false` 则平台按钮照常拿到点击 | 案例里「普通按钮喂不消费 / 开关消费」两条路都对 |
| 按下态 | 按住期间抓帧，填充色/轨色确实变深（像素探针实测） | `zzb_05*_pressed_*`、`zzb_10*` |
| 药丸 + 圆钮 | 56×28 药丸（半径 14）+ 22px 白钮，开/关钮位左右对称；放大 8× 边缘无阶梯 | `zzb_0*_zoom8x_pill_*.png` |
| **圆钮不再露方角**（0.1.1 修复） | 判据：理想药丸轮廓（16×16 超采样、覆盖率 < 0.30）外的**纯药丸色**（三通道最大差 ≤ 12）像素数。修前 **6/钮**（正是钮盒两个外上/外下角，像素点固定不动），修后 **0/钮**，两个开关 × 开/关四帧都一样 | `z21/evidence/zzc_0*_switch_*`、`zzc_*_zoom8x_pill_*`、`zzc_metric.log`（案例 STATUS §12） |
| 主色跟随 | 换主色后 `setColors(...)` + `refresh()` 立即生效（药丸开态轨色 / Log out 填充都跟着变） | 案例 `applyPrimary()` → `zzb_20*` |

### 5.3 与「平台按钮」的三种共存方式（选一种，别混）

| 方式 | 屏上谁画 | 点击谁收 | 适用 |
|---|---|---|---|
| A. 纯 painter（本包独占） | 包 | 包（`onTouch` 消费） | 开关、自绘控件；文字要另想办法（painter 无文字 API） |
| B. painter 在下 + 平台按钮（透明切图）热区在上 | 包（倒角）+ 按钮（文字/图标） | 平台按钮（包**不消费**，只显示按下态） | 动作按钮——案例里的主用法 |
| C. painter 在上 + 平台按钮在下 | 包（**按钮的文字会被盖住**，因为 painter 铺设不透明底） | 平台按钮 | 不推荐（除非按钮无文字/图标） |

⚠️ 方式 B 的接线坑（`html2json` 侧）：文字按钮去掉 `data-bg` 会被自动填 `bgColorTab = 0x374457`；
给它挂一张**全透明切图**即可（有 `picTab` 时 html2json 会自动去掉 `bgColorTab`）。
细节见 README §12 末段。
