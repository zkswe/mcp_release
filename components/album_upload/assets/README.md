# assets —— 相册传图的二维码 URL 口径

> 本目录只有一件事：**二维码的"内容"从哪来**。传图本体在 `../README.md` 指向的 `components/mp_transfer/`。
> **面板上不铺任何二维码位图**（本目录原来的 `album_qr_mp128.png` 已删除）：只给"链接字符串"，
> 由 `ZKQRCode` 控件**现场生成**。

## 1. 一句话口径（一条路 + 一个兜底）

| 来源 | 什么时候走它 | 上屏方式 |
|---|---|---|
| **① 配置 URL** | 部署方在配置（如 prefs `sp_qr_url`）里给了小程序链接 | `ZKQRCode::loadQRCode(<链接>)` |
| **② 本机上传地址兜底** | ① 为空（没配 / 被清空） | 同上（内容换成 `http://<ip>:9000/upload`，联调保底，不是给终端用户的入口） |

两条路的**处理方式完全一样**：把 `QrInfo::content` 交给控件。区别只是"这串内容从哪来"，
组件用 `QrMode` 告诉你（`QR_FROM_CONFIG` / `QR_LOCAL_UPLOAD_FALLBACK`）。

## 2. 为什么不用位图（本目录曾经的素材为什么删了）

微信给的小程序码图有 **37 个模块**；面板上二维码控件盒是 **128×128**：
`128 / 37 = 3.46 px/模块` —— **模块宽不是整数像素**，缩放必然产生灰边 → 真机上就是"边缘发糊、扫不动"。
把图做大只是把问题往后推（盒子还是 128），把图做小更糟。

**`ZKQRCode` 现场生成的优点**：控件拿到**链接字符串**后按自己的模块栅格绘制 →
**每个模块落在整数像素上**（像素对齐、边缘锐利），且不受"原图分辨率 / 缩放算法"影响；
码的尺寸跟着控件盒走，换盒子（128→160…）不用重出素材。

## 3. URL 从哪来 / 换成你自己的

两种取法，任选其一：

1. **小程序后台**：微信公众平台 → 开发 → 开发设置 → **扫普通链接二维码打开小程序**，
   配好规则后拿到的链接（本次口径就是这种"链接码"）；
2. **从商家/微信给的码图里解出来**（离线一次性）：用本目录上一级的脚本
   `../scripts/decode_qr_url.py`（见 §4）。

本仓附了一个**示例值**：`qr_url.txt`（一行 = 我方小程序码解出来的链接）。

> ⚠️ **换成你自己的小程序链接**：`qr_url.txt` 里的链接是**我方小程序**的，
> 你部署到自己的产品时必须换成自己小程序后台生成的那条（或自己的配置项值）。
> 组件本身**不带任何默认链接**：`Config::qr_url` 空 → 走本机上传地址兜底。

> ⚠️ **AppID 不写死**：`Config::mp_app_id` 只是**记录/业务用**，不参与本机生成二维码；
> AppID 与链接一律由部署方在**自己的配置**里给，仓库里的代码/文档不带我方 AppID。

⚠️ **静区**：二维码四周要有白边（≈4 模块）才扫得动，靠**布局**给
（来源工程：160×160 白卡 + 128 码居中 = 四边各 16px 白边）；控件盒贴到深色底/贴边会扫不出来。

## 4. 怎么从一张码图里解出链接（离线工具，运行时不依赖图片）

```bash
# 在 components/album_upload/ 目录下执行（一次性）：
# 把伙伴/微信给的码图里的链接解出来 → 填进你的配置项（如 sp_qr_url）
py scripts/decode_qr_url.py --src mp_qr.png
# 想把解出的链接直接写进 assets/qr_url.txt（与仓里那份同格式）：
py scripts/decode_qr_url.py --src mp_qr.png --write assets/qr_url.txt
```

- 脚本**只在换码/换小程序时跑一次**，依赖 `Pillow` + `zxing-cpp`（`py -m pip install pillow zxing-cpp`）；
- **组件运行、设备上屏都不需要任何图片，也不需要这个脚本**（本目录没有位图素材）；
- 解不出就换一张更清晰的源图（**别拿缩到 128 的糊图当源**，模块太小解不稳）。

## 5. 与组件 API 的对应

| 口径 | `zk::album` 里的对应 |
|---|---|
| ① 配置 URL | `QrInfo{mode=QR_FROM_CONFIG, content=<qr_url>}` → `loadQRCode(content)` |
| ② 本机地址兜底 | `QrInfo{mode=QR_LOCAL_UPLOAD_FALLBACK, content=local_url}` → `loadQRCode(content)` |
| 换内容 | `setQrUrl(从 prefs 读到的链接)`；传空串 = 退回兜底（内容变了才需要重新 `loadQRCode`） |
| 页面销毁 | **业务侧**清自己那份"已 load 的内容"缓存（组件不缓存二维码内容，见 `../README.md` §6 坑 1） |

（详见 `../include/zk/zk_album.h` 的 `QrMode` / `QrInfo` 注释。）
