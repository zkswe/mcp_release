# platforms.md —— icons 模块的平台说明

> 结论先说：**本模块是全平台通用的纯资源库**。产物是标准 32-bit RGBA PNG（8bit/通道），
> 图形源是 Tabler SVG（MIT）与少量自绘，**不含任何平台代码、不依赖任何底层包、不需要 `fun install`**。
> 任何一个能跑 FlyThings/zkgui 的平台都能直接用它生成的图片。
> 建立：2026-09-15｜更新：2026-09-17（v0.3.0：vendor SVG 收进单归档，按需解，离线优先）

---

## 1. 平台可用性一览

| 平台 | 可用性 | 说明 |
|---|---|---|
| **全平台（F133 / Z20 / Z21 / V85X / T113 / MCU Lite）** | 可用 | 纯 PNG 资源：生成的图与平台无关；差异只在分辨率/色深/是否硬件加速贴图 |
| V85X | 可用 | 天气/界面图标已在 `projects/inSightOS3` 项目里实际使用过（旧版为自绘天气图，v0.2.0 起换成 Tabler 同名图标） |
| F133 / T113 | 可用 | 高分屏建议 `--size 32/44/56` |

| MCU Lite | 可用（未验证） | 内存更紧：只拷用得上的图标（单张 22px ≈ 0.3 KB） |

v0.2.0 只做了**离线像素级验收**（selfcheck + contact sheet，含 22px 专项），真机投递未验证。

## 2. 三条硬规则（跨平台都一样）

### 2.1 颜色是烘焙进 PNG 的（没有 tint API）
FlyThings/zkgui 的图片控件（`backgroundPic` / `picTab`）**没有运行时染色接口**，也不支持
CSS 那种 `filter`/`mask`。因此：

- 同一图标的不同颜色 = **不同 PNG**。白 `255,255,255`、浅色主题 `51,51,51`、
  强调色 `0,122,255` 都要各自生成一套：
  ```bash
  python scripts/gen_icons.py --set system --size 24 --color 255,255,255 --out <项目>/app/resources/images
  python scripts/gen_icons.py --set system --size 24 --color 51,51,51  --out <项目>/app/resources/images/light
  ```
- 本模块的 PNG **RGB 全等于 `--color`**，只让 alpha 变化（不做灰阶叠加）。所以同一张图放在
  深/浅底上都干净，不会出现"灰边"。
- 两态图标的 `on` 态用**真透明挖空**（如 toggle 的白圆钮），挖空处露底图颜色 —— 换主题时
  不用重新出图，只要底图换色即可。

### 2.2 图片像素尺寸必须严格等于控件 `position`
zkgui 的图片控件默认按控件盒拉伸（不做等比 letterbox）。图片像素尺寸 ≠ 控件宽高时：
- 视觉上被拉伸/压扁（22×22 的图放进 30×30 的盒 → 图标变胖、线条变粗）；
- `flythings_verify_assets` 会报"自动生成图 PNG 尺寸 == 控件 position"不通过。

本生成器保证**产物像素尺寸严格 == `--size`**（`selfcheck.py` 的 B 项断言）：
```
--size 22    →  json 里 "position": {"width": 22, "height": 22}
--size 56    →  json 里 "position": {"width": 56, "height": 56}
--size 22x16 →  产出 22×16（按 16 边等比缩放 + 水平居中留白，**不拉伸**）
              json 里 "position": {"width": 22, "height": 16}
```
非正方形只在确实需要长条图标（如箭头的横版位）时用；**不要**靠拉伸让方图适配长方盒。

### 2.3 设备字库不放图标（图标一律走图片）
`components/fonts/` 的字库用于**文字**。把图标做成图标字体在设备端不可行：
- zkgui 的字体渲染只取字形轮廓，无法在 22px 上做像素对齐（线条糊、对齐飘）；
- 字体只支持单色 + 有限 hinting，做不到本模块的"线宽随尺寸整数化"；
- 换色同样需要重做字体文件，收益为零。

另外：Tabler 图形是**几何路径**，转字形还要额外描边化（等于改图形，见 `THIRD-PARTY.md`）。
所以：**文字用 `components/fonts/`，图标用本模块的 PNG。**

## 3. 随包投递与升级

- 图片资源放在工程 `<项目>/app/resources/images/`，`fun build` 时随 app 打进包里（设备上为 `/res/...`）。
- **出升级包会整体替换目标机的 `/res`** → 图标必须随包走，不能只推单个文件到设备（推了也会被下次升级清掉）。
  与 `components/fonts/README.md` 第 5 节是同一个坑。
- 只拷**用到的**图片。305 张全拷虽然也只有几十 KB，但会让 `verify_assets`/包清单变长，
  排查"图哪来的"变困难。
- **设备端 / 产品包里不包含 vendor 归档**：`vendor/tabler-3.46.0.pack.tgz`（455 KB）只是
  **仓库侧的矢量源形态**（打开发 PNG 用），设备只看到烘好的 PNG。
- **生成不需要联网**（离线优先）：SVG 从归档按需解到 `out/.icons-cache/`；只有显式
  `--fetch-remote` 才会按 `catalog.json` 的 npm URL 拉取（带 sha256 校验）。

## 4. 真机验收（每个平台各做一次）

```
1) 生成到工程并编译：
   python scripts/gen_icons.py --set all --size 22 --out <项目>/app/resources/images
   fun build -p <平台>          # 或 flythings_build_ui_flow
2) 推真机 + 抓屏：
   fun launch -p <平台>         # 临时调试
   flythings_device_screenshot()  # 直接抓画面
3) 看三件事：
   · 图标是否被拉伸（对比 contact sheet 里的形状）
   · 22px 图标线条是否发虚（若虚：检查控件盒是否 == 22，见 §2.2）
   · 深色底上是否有灰边（本模块产物 RGB 恒为纯色，出现灰边说明是屏的色深/缩放问题，不是图的问题）
4) 像素级验收（可选）：
   flythings_ui_visual(action="diff", image_a=<设计稿>, image_b=<抓屏>)
```

**实测记录**（跑过就填，别写"应该可以"）：

|---|---|---|---|

## 5. 已知限制（与平台相关）

1. **色深**：若屏是 RGB565（16bit），单色图标在斜线边缘可能有 1px 色带；本套用"半像素对齐线宽 +
   单色烘焙"把这种观感降到最低，但无法完全消除（那是屏的量化误差，不是图的）。
2. **透明通道**：zkgui 部分老版本对带 alpha 的 PNG 走软件合成，图层叠加过多会掉帧。
   图标本身很小（22px），实际影响可忽略；若确实掉帧，优先合并背景图。
3. **缩放动画**：如果要对图标做缩放动效，**每个中间尺寸都出一张图**（或预先出 22/32/44/56 四档），
   不要依赖控件缩放——拉伸会破坏线宽整数对齐。
4. **深色/浅色双主题**：需要两套 PNG（同 §2.1），工程里用不同目录区分（如 `images/` 与 `images/light/`），
   切换主题时整屏重建布局 json 或按主题选不同的 `backgroundPic` 字符串。

## 小尺寸策略（实测，2026-09-16）

Tabler 的线宽是 2px@24 网格；缩到 22px 时只剩 ~1.83px。本套生成器用
「**半像素对齐线宽 + α 对比度整形（0.40/0.60 过渡带）+ 去雀斑**」处理，
实测 22px 中间值像素 ≤ 9.7%、边缘不发虚：

| 控件尺寸 | 用法 |
|---|---|
| **>= 22px** | outline 即可（本套已整形，22px 不糊） |
| **<= 20px** | 建议 filled（实心），密集图形（toggle/bell/bulb）更清楚 |
| <= 16px | 未纳入默认清单，需要时用 `--size 16` 自行确认 |

> 复核口径：`python scripts/selfcheck.py`（C 项：中间值像素占比 <=15%、无孤立半透明噪点）。
