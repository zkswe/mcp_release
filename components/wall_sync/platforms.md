## 1. 支持矩阵

| 平台 | 可用性 | 说明 |

## 2. Z20（可用）

### 2.1 前置条件（不满足就不同步）

| 前提 | 要求 | 不满足的后果 |
|---|---|---|
| 网络 | 同网段互通，允许 UDP 广播（关掉交换机广播抑制/客户端隔离） | 收不到 epoch → 各自轮播（`Sync::readyToPlay()` 为 false） |
| 时间 | **各机都完成 NTP 校时**（默认网关优先 + 内置公网兜底） | 相位随钟差漂移（钟差大时两台可差 ≈10 帧）；`clockPlausible()==false` 时组件**不起播** |
| 型号/方向 | 同型号、同分辨率、同安装方向（统一旋转角） | 画面切分对不上 |
| 素材 | 同一 clip 内各机那段 `seg_<序号>.mp4` **严格等长（差异 ≤40ms）**；不同 clip 之间可长短不同 | 循环缝变大 / 末帧冻结 |
| 固件 | 两台 `/res/lib/libzkgui.so` md5 相同 | 行为不一致、难定责 |
| 播放状态 | 面板处于**屏保**状态（主页/设置页时拼接暂停） | 不进屏保不拼接（设计如此） |
| 磁盘 | 素材/清单放设备盘 `<wallRoot>`（默认 `/mnt/sdnand/wall`）；`/mnt/sdnand` 只有 **75MB** | 大组放不下 → 用 `--only-mine` 只推本机那一段 |
| 引擎 | 官方包 `simple-player`（**带授权码**，见 `Manifest.xml`） | 没有引擎 = 组件不送流（`Player::start()` 返回 `ZW_ENO_ENGINE`） |

### 2.3 已知限制（在 Z20 上）

1. **≤4 台**，仅**单行横排 1xN**；不支持 2×2 等二维排布；主从需**人工设置**（无自动选举）；从机改配置需停/启应用或重新进屏保才生效。
2. **只在屏保状态拼接**（主页/设置页暂停）。
3. **必须 NTP 校时**（面板 RTC 掉电不保时）；掉电后未校时会 `clock_insane` / 不播（组件用 `clockPlausible()` 守卫）。
4. **残差 ±19ms** 主要来自 1s tick 回调调度抖动（观测 ~9~19ms）；要再压低需更细粒度定时源。
5. **长跑时钟漂移**：两机各自 NTP 后靠晶振自由跑（趋势 ~−0.9ms/min，在噪声内）；要 24h 稳定 ≤1 帧需定期测钟差。
6. **循环缝 ~160ms**（两段式提前停造成末帧冻结/截断）；想零截断可让栅格比源片长 200~400ms（缝变大但内容完整）；多 clip 模式不按周期截断。
7. **截图拿不到视频层**（视频不在 `/dev/fb0`）：`device_screenshot` 只能拿 UI 层 → 终验必须**相机拍屏**，设备侧用 §2.4 的 `mi_disp0` 自证。
8. 设备 shell **无 `md5sum`/`grep`**（要 `adb pull` 回本机算，或推 busybox）。
9. 设备盘 `/mnt/sdnand` **只有 75MB**。
10. ⚠️ **Z20 上 `/mnt/extsd/EasyUI.cfg` 的 `startupLibPath` 会劫持**（加载 SD 卡上的旧库/界面，表现 = "推上去没效果/画面是旧的"）：改回或删掉该文件后重启应用。
11. ⚠️ **播放中改配置 / kill 应用可能让 MI 驱动卡死**（进程 D 态、`wchan=MI_SYS_IOCTL_Init`）→ 改完 pref **重启整板**，别在播放中 kill。
12. ⚠️ **两个内核不能同时上屏**：官方包 simple 引擎与 easyui 的 `ZKVideoView` 抢 MI 图层；`stop()` 的图层拆解是**异步**的，紧接着起另一个会留下**永不 finish 的 workingTask**（`mi_disp0` 里 chn0 `UsrInjectQ/workingTask/FinishCnt` 卡住）→ 表现"屏保画面冻住不动"。处置 = 总闸 + 停后**沉降 400ms**（见 `example/flythings_wiring.cc`）。
13. 平台侧：Z20 拼接走**本机自建硬解**（MI VDEC + MI DISP）；easyui 自带 `zkmedia` 在 Z20 是**软解（FFmpeg）**，不参与拼接。

### 2.4 真机验收步骤（Z20）

1. 两台同型号面板，同网段；都确认完成 NTP（看 `ClockManager` 同步日志 / `Sync::skewSrc()` 为 `pingpong`）。
2. 用切块工具生成整组素材推到**各机**盘上（`<wallRoot>/<组名>/`，含 `playlist.json`），确认各机 `/res/lib/libzkgui.so` md5 一致。
3. 配好 `sp_wall_en/group/idx/n/role`（或只推素材让零配置推导），两机进屏保。
4. **主判据**：两机日志按同一 `cyc/pts` 配对求 `|Δnow|` → **≤40ms**（1 帧 @25fps）；多轮稳定。
5. **旁证 A**：`D/zkmedia: play: <seg>.mp4` 相对同一边界的差。
6. **旁证 B**：切换/回卷时刻 Δ ≤1ms、同帧；`reopen` 行 `dropGop=0`。
7. **画面质量**：设备端抓 YUV 算**块度 ≤1.2**（源帧基准 1.05~1.25）。
8. **客观自证**：`/proc/mi_modules/mi_disp/mi_disp0` 层状态（`bind mi_vdec chn1`、480×480、`FPS 25.02`、`FinishCnt` 递增）；终验用**相机拍两块屏**（截图拿不到视频层）。
9. ⚠️ 同一批设备**同一时刻只允许一个会话部署/抓日志**（并行部署会互相覆盖日志，结论反复）。

## 3. 换平台（非 Z20）先查三件事

1. **能注入引擎吗**：目标平台有没有"阻塞式播放 + 从外部线程 stop + 自带帧对齐"的播放器（或自研一个实现 `zk::wall::Engine`）；有没有可用的硬解通道（Z20 = MI VDEC/DISP）。
2. **墙钟能被校到毫秒级吗**：`Sync::nowMs()` 拿到的必须是**绝对墙钟毫秒**（≥1e12）；若平台只能给秒级，相位永远收敛不到 1 帧（真源踩过）。
3. **网络与磁盘**：能否 UDP 广播/UDP 单播互通；素材放哪、够不够（Z20 实测盘只有 75MB）。
   → 三条都过一遍、并**在该平台重做 §2.4 的验收**，才能把结论从 `未验证` 改成"可用"。
